# Аудит исходного spec.md перед переписыванием

Проверяемая версия: commit `df9c643`, `spec.md` версии 0.1.0.

## Findings

1. **Critical · строки 31–32, 475–489.** Заявлено использование только
   встроенных инструментов Codex, но автоматический alignment передан локальной
   Whisper-compatible модели. Не определена граница между Codex-сессией и
   автономным worker, а встроенные инструменты Codex ошибочно описаны как API,
   доступный приложению. Исправление: сделать Codex явным интерактивным
   исполнителем редакционной стадии; worker не вызывает Codex. Локальное ASR
   назвать отдельной offline media dependency и закрепить отсутствие внешнего
   AI API.

2. **Critical · строки 559–565, 703, 717–720.** Docker Desktop и WSL2 выбраны
   без требования владельца и создают лишние точки отказа для Windows-ноутбука:
   bind mounts, startup Docker, GUI-login Дзена и wake chain. Исправление:
   Windows-native worker; контейнер допускается только как заменяемая деталь,
   если Telegram capability test докажет необходимость.

3. **Critical · строки 167–169, 202–204, 559–565.** `armed` смешивает нативную
   отложку площадки и локальную job. Если ноутбук выключен, YouTube/Дзен могут
   стать публичными, а Telegram нет, причём локальная система не сможет заранее
   компенсировать. Исправление: v1 готовит private/draft ресурсы, но публичное
   переключение всех трёх инициирует локальный coordinator в target time; missed
   target без одной public публикации переводит весь Выпуск в delayed.

4. **Critical · строки 187–190, 210–229.** Business state разделён между JSON,
   JSONL и SQLite, хотя атомарной транзакции между ними нет. Упомянутый «журнал
   намерения» не специфицирован. Исправление: одна SQLite database является
   каноническим transactional state и outbox; файлы хранят bytes, а
   `release.json` становится воспроизводимым экспортом Манифеста.

5. **High · строки 102, 560–565.** Одноразовый ручной вход в Дзен не имеет
   исполнимого UX: контейнерный browser profile и headful login не согласованы с
   Windows. Исправление: setup-команда открывает Playwright Chromium на Windows,
   Sardor проходит login/MFA, затем сохраняется отдельный локальный profile.

6. **High · строки 60, 491, 516, 503, 547–553, 625–626, 666–676.** Множество
   чисел выданы как требования без основания: 470–820 слов, confidence,
   retries, 20 GiB, retention, RPO/RTO, p95. Исправление: оставить подтверждённые
   продуктовые лимиты; технические стартовые параметры маркировать как
   versioned defaults с обязательной калибровкой либо удалить.

7. **High · строки 572–573.** Требование одного GitHub approval блокирует merge,
   если изменения отправляет единственный владелец: автор PR не может одобрить
   собственный PR. При этом CI workflow ещё не существует. Исправление:
   обязательный PR + CI; независимый review хранится как evidence. GitHub approval
   становится обязательным только после добавления второго reviewer account.

8. **High · строки 110–112, 698–699.** Не доказано, что Dzen draft даёт будущий
   URL, который можно вставить в Telegram до публикации, и не определён fallback.
   Исправление: Dzen capability spike является release gate; если URL появляется
   только после публикации, coordinator публикует Дзен первым, получает URL и
   только затем отправляет Telegram в пределах drift SLO.

9. **High · строки 544–549.** `Docker secrets под %PROGRAMDATA%` не является
   точным Windows security contract. Обязательный BitLocker введён без проверки
   редакции Windows и доступа к настройкам. Исправление: Windows Credential
   Manager/DPAPI для секретов приложения, ACL для data root; encryption status
   проверяется и сообщается, но не маскируется выдуманной гарантией.

10. **Medium · строки 91–96, 328–355.** Для одного пользователя введены
    multi-profile extension, RBAC и абстракции, которые не нужны v1 и расширяют
    поверхность реализации. Исправление: один Windows account, два логических
    actor labels и state guards; multi-user/RBAC оставить вне scope.

11. **Medium · строки 513–518.** Alert использует тот же Telegram bot, что и
    публикация. При отказе bot token/API аварийный канал тоже не работает.
    Исправление: зафиксировать это как общий failure domain; локальный incident
    file и Windows notification являются обязательным вторым сигналом.

12. **Medium · весь документ.** 38 обязательных разделов заполнены, но многие
    стали энтерпрайз-шаблоном вокруг однопользовательской утилиты. Контракт
    сложнее удерживать, а повторения расходятся. Исправление: сохранить структуру
    skill, но явно помечать неприменимые области и ссылаться на единственные
    канонические таблицы вместо повторного описания.

## Gate

Результат: rewrite required. Критические findings 1–4 не позволяют считать
версию 0.1.0 build-ready.
