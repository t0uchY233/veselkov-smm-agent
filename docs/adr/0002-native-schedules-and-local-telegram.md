# ADR 0002: нативная отложка YouTube и Дзена, локальная отложка Telegram

- Статус: принято
- Дата: 2026-09-03
- Решение: Sardor

## Контекст

YouTube умеет нативно публиковать private video по `publishAt`. При создании
отложенной публикации Дзена рабочая ссылка на будущую статью уже доступна.
Telegram Bot API не умеет планировать отправку сообщения, а production работает
на одном ноутбуке Windows 11, который может оказаться выключенным в target.

## Решение

После финального gate worker создаёт и проверяет нативные отложки YouTube и
Дзена. Полученные ссылки YouTube и Дзена механически подставляются в заранее
утверждённые link slots Telegram caption. Telegram ставится на то же время через
SQLite и Windows Task Scheduler.

T−30 preflight при доступном ноутбуке проверяет все три расписания. До первого
public результата он отменяет доступные schedules при общем сбое. После target
reconciliation читает фактические remote states и повторяет только отсутствующую
операцию с прежним idempotency key.

## Отклонённые варианты

- Полностью локальный coordinator: делает все три площадки зависимыми от
  бодрствования одного ноутбука.
- Telegram после подтверждённого public Дзена: не нужен, поскольку ссылка
  отложенной статьи уже известна.
- Облачный scheduler: добавляет отдельный runtime и секреты вне выбранного
  Windows-native контура.

## Последствия

- YouTube и Дзен могут выйти вовремя при выключенном ноутбуке.
- Telegram зависит от Windows Task Scheduler и может опоздать до следующего
  запуска ноутбука.
- Физическая атомарность невозможна. Частичный выпуск не маскируется: создаётся
  incident, а Telegram восстанавливается без повторной публикации YouTube/Дзена.
- Capability smoke Дзена обязан подтвердить identity статьи, target и
  стабильность ссылки, полученной до публикации.
