# ADR 0001: локальный оркестратор и поставка через GitHub Releases

- Статус: принято
- Дата: 2026-09-03
- Решение: Sardor

## Контекст

Codex должен остаться единственной точкой общения с Автором, но prompt-only
агент уже показал нестабильность: пропускал стадии и зависел от памяти человека.
Публикация по времени и поиск локальной видеозаписи должны продолжаться при
закрытом диалоге. Новую систему также требуется версионировать и отлаживать по
тому же artifact-driven SDLC.

## Решение

Codex является разговорным интерфейсом, а состояние, gates, фоновые задачи и
внешние эффекты принадлежат локальному детерминированному оркестратору и worker.
Канонический код и SDLC-артефакты хранятся в публичном GitHub-репозитории;
runtime data, реальные конфиги, секреты и пользовательские медиа туда не
попадают. Production устанавливается только из версионного GitHub Release с
проверяемыми SHA-256 checksums, собранного GitHub Actions после обязательных
проверок.

## Отклонённые варианты

- Prompt-only агент: не гарантирует порядок стадий и работу по расписанию.
- Отдельная web-панель: создаёт Автору второй интерфейс и не нужна в v1.
- Ручное копирование файлов на production: не даёт воспроизводимой версии и
  безопасного rollback.

## Последствия

- Нужны CLI-контракт, локальный worker, durable queue и Манифест Выпуска.
- Git commit, release tag и версия приложения должны попадать в диагностику.
- Любое production-обновление должно иметь проверяемый путь rollback на
  предыдущий GitHub Release.
- GitHub недоступен во время выпуска не мешает уже установленной версии
  завершить текущий Выпуск.
